# Gmail 自動分別（Google Apps Script 版）

会社の Gmail に届いたメールを AI（**Jev** または **Clef**）に判定させ、Gmail のラベルを付けるツールです。
スプレッドシートに組み込まれたスクリプトなので、自分のサーバーは要りません。15分ごとに Google 側で自動で動きます。

- できること: ラベルを付けることだけです。メールの削除、移動、送信、既読化はしません。
- 判定に自信がないメールは「要確認」ラベルに回し、人が見ます。
- 最初は「記録のみ」で動きます。ラベルは付けず、判定結果をシートに残すだけです。正しさを確かめてからラベル付けを始めます。
- カテゴリ（選択肢）は「カテゴリ」シートに1行足すだけで増やせます。

## 1. 使う前の確認（会社のルールと管理者設定）

### 会社のルール

このツールは、判定のためにメールの一部を社外の AI サービスに送ります。使う前に、社内のルールで次の点が許されているかを確かめてください。

- **送る内容**
  - メール1通ごとに: 差出人、宛先（To）、件名、送信日時、メーリングリストの印（`List-Unsubscribe` ヘッダーがあるか）、本文の先頭（既定は2,000文字。引用された過去のやりとりは除きます）。
  - 毎回いっしょに: 「設定」シートの「あなたの仕事」と「返信が必要なメールの目安」、「カテゴリ」シートのカテゴリ名と説明。
  - 添付ファイル、Cc、ほかのヘッダーは送りません。
- **送り先**: どちらか一方だけです。
  - Jev: TypeSafe 社（`https://api.typesafe.ai/v1/systemone`）
  - Clef: Cloudflare 社の Workers AI（`https://api.cloudflare.com/client/v4/accounts/<アカウントID>/ai/run/@cf/cloudflare/clef`）
- 各社の公開文書（2026年10月時点で確認）では、次のとおりです。契約の前に、最新の文書を自社で確かめてください。
  - Cloudflare: 顧客のコンテンツを学習に使わず、処理のあとに保持しないと説明しています。ISO 27001 と SOC 2 Type II の認証があります。
  - TypeSafe: データ処理契約（DPA）があり、漏えいを72時間以内に通知するとしています。データをまったく保持しない契約（ZDR）は、エンタープライズ契約に限られます。

### Google Workspace の管理者に確認すること

管理コンソールの項目名は変わることがあります。次は2026年10月時点のヘルプにもとづきます。

1. **Apps Script を使えるか**: 組織で Apps Script が無効になっていると動きません。
2. **API の制御**（セキュリティ → アクセスとデータの管理 → API の制御）
   - このスクリプトは Gmail の `gmail.modify` スコープを使います。Gmail は「制限付き」に設定できるサービスで、送信などの高リスクなスコープを個別に止められます。
   - 社内で作ったアプリ（Apps Script を含む）を信頼する設定や、Gmail へのアクセスが許されているかを確認してください。
   - 管理者は、どのアプリがどのスコープを許可されたかを監査でき、あとから取り消すこともできます。
   - Apps Script のデータアクセスを監視したり制限したりする機能は、Enterprise、Education Standard、Education Plus のエディションでしか使えません。
3. **外部への通信**: スクリプトが社外の URL（上の2つ）に接続できる必要があります。

## 2. 使い方（利用する人）

配布する人から「コピーを作成」のリンクを受け取ったところから始めます。

### 1) コピーを作る

リンクを開いて「コピーを作成」を押します。コピーは**自分のマイドライブ**に置いてください。共有ドライブでは動きません（理由は[6章](#6-安全のためのしくみ)）。

### 2) はじめに設定する

1. コピーしたスプレッドシートを開くと、上のメニューに「**自動分別**」が出ます（数秒かかることがあります）。
2. 「自動分別 → **はじめに設定する**」を選びます。
3. 初回だけ、Google の許可画面が出ます。表示された権限をすべて許可してください（どれかを外すと動きません）。
   - 「このアプリは Google で確認されていません」と出ることがあります。これは、自分でコピーしたスクリプトを自分で動かすときに出る表示です。コードは「拡張機能 → Apps Script」でいつでも中身を見られます。
4. 設定画面で次を入れて「**保存して接続テスト**」を押します。
   - **AIサービス**: Jev / Clef / Clef Flash
   - **APIキー**
     - Jev: TypeSafe で発行したキー
     - Clef: Cloudflare の API トークン（Workers AI の権限だけを付けて作ってください）と、アカウントID（32文字の英数字）
   - **あなたの仕事**（任意）: 例「営業部で法人顧客を担当」。入れると精度が上がります。
5. 「設定できました」と出たら完了です。15分ごとに自動で動きます。

接続テストでは、ツールに入っている**作り話の例文**を送ります。あなたのメールは送りません。

### 3) しばらく「記録のみ」で確かめる

- 「**記録**」シートに、判定したメールが1行ずつ増えます。
- G列「判定は正しい？」に ○ か × を付けてください。
- 「自動分別 → **正解率を見る**」で、全体と結果ごとの正解率がわかります。
- 「要確認」が多すぎるとき、または少なすぎるときは、[設定項目](#4-設定項目)のしきい値を調整します。
  - 「記録」シートには、分類の確信度、返信が必要な確率、自動送信の確率、緊急度も残ります。× を付けた行の数値を見ると、しきい値をどこにすればよいかの見当がつきます。
  - しきい値を変えると、そのあとに判定するメールから効きます。

### 4) ラベル付けを始める

正解率に納得できたら、「自動分別 → **ラベル付けを開始する**」を選びます。Gmail に次のようなラベルが付きます。

| ラベル | 意味 |
|---|---|
| `自動分別/<カテゴリ名>` | 分類の結果 |
| `自動分別/要返信/今日` | 返信を待っている人がいて、急ぎ |
| `自動分別/要返信/今週` | 返信を待っている人がいるが、1〜2日は待てる |
| `自動分別/要確認` | AI に自信がない。人が見る |

### そのほかのメニュー

| メニュー | すること |
|---|---|
| 今すぐ1回実行 | 15分待たずにすぐ1回動かします |
| 接続テスト | 許可、共有、Gmail、通信先の制限、AI サービス、自動実行を順に確かめます |
| 記録だけに戻す | ラベル付けをやめます。付けたラベルは残ります |
| 自動実行を止める | 15分ごとの実行を止めます |

### やめるとき

1. 「自動分別 → 自動実行を止める」を選びます。
2. 許可を取り消すには、Google アカウントの「セキュリティ → サードパーティ製のアプリとサービス」から、このスクリプトを削除します。
3. ラベルが要らなければ、Gmail でラベルを削除します。ラベルを削除してもメールは消えません。

## 3. カテゴリの増やし方

「**カテゴリ**」シートに1行足すだけです。

| カテゴリ名 | どんなメールか（AIへの説明） | 一時的に外す |
|---|---|---|
| 採用 | 応募者や人材紹介会社からのメール。 | ☐ |

- **カテゴリ名**は、そのまま Gmail のラベル名になります（`自動分別/採用`）。
- **説明**は、AI がどのカテゴリかを決める手がかりです。「誰から」「何の用件か」を書くと精度が上がります。件名の言葉より、送り主と用件で書くのがこつです。
- 「**一時的に外す**」にチェックを入れると、その行は使いません。
- 決まりごと
  - 名前に「/」は使えません。「その他」「要確認」「要返信」はツールが使う名前なので、カテゴリ名にはできません。
  - 同じ名前は2つ作れません。
  - カテゴリは254個までです（AI の選択肢の上限は255個で、そのうち1つは自動で付く「その他」です）。
- 問題があると、実行は止まります。何行目が問題かは「実行履歴」シートか、メニューの表示で知らせます。

最初に入っているカテゴリは次のとおりです。自由に変えてかまいません。

- 顧客・取引先
- 社内の連絡
- 会議・日程
- 請求・経理
- システム通知
- メルマガ・お知らせ
- 営業・勧誘

## 4. 設定項目

「**設定**」シートの B 列を書き換えます。空欄にすると既定値に戻ります。

| 項目 | 既定値 | 説明 |
|---|---|---|
| 動作モード | 記録のみ | 「記録のみ」か「ラベル付与」 |
| AIサービス | Jev | Jev / Clef / Clef Flash |
| あなたの仕事 | 会社で働いている人。仕事のメールを受け取る。 | 判定の手がかり。500文字まで |
| 返信が必要なメールの目安 | （空） | 例「社外からの質問と、上司からの依頼は返信が必要」 |
| ラベルの親の名前 | 自動分別 | ラベルはこの名前の下に作られます |
| 何日前までのメールを見るか | 2 | 1〜30。受信トレイのうち、この日数以内に届いたもの |
| 1回に判定する最大件数 | 50 | 1〜200。残りは次の回に回します |
| AIに送る本文の最大文字数 | 2000 | 詳細設定。200〜8000 |
| 分類の確信度の下限 | 0.75 | 詳細設定。これ未満なら要確認 |
| 返信要否の迷いの下限 | 0.4 | 詳細設定 |
| 要返信と見なす確率 | 0.6 | 詳細設定 |
| 自動送信と見なす確率 | 0.5 | 詳細設定 |
| 「今日」と見なす緊急度 | 1.5 | 詳細設定。緊急度は0〜3 |

確率のしきい値は0〜1で書きます。「75%」のようにパーセントで書いてもかまいません。

APIキーはこのシートに**書きません**。メニュー「はじめに設定する」で入れると、あなたの Google アカウントの中にある、このスクリプト専用の保存場所（UserProperties）に入ります。

## 5. 判定のしくみ

メール1通につき、AI に4つの質問を1回のリクエストでまとめて聞きます。質問はたがいの答えを見ずに、それぞれ独立に答えます。

| 質問 | 型 | 返ってくるもの |
|---|---|---|
| どのカテゴリか | 選択（choice） | 選ばれたカテゴリ、各カテゴリの確率、確信度 |
| 差出人はあなたの返信を待っているか | はい・いいえ（noul） | 「はい」の確率 |
| システムや一斉配信からのメールか | はい・いいえ（noul） | 「はい」の確率 |
| どれくらい急ぎか | 段階（score、0〜3） | 確率で重み付けした値 |

AI は確率を返すだけです。ラベルを決めるのはツール側のコード（`src/Classifier.gs` の `decide_`）で、上から順に当てはめます。

1. 分類が「その他」か、分類の確信度が0.75未満なら、**要確認**にします。
2. 返信が必要な確率が0.4以上0.6未満なら、**要確認**にします。返信が必要かどうかは、迷ったときに人が見る価値がある問いだからです。
3. 返信が必要な確率が0.6以上で、自動送信の確率が0.5未満なら、**カテゴリと要返信**のラベルを付けます。緊急度が1.5以上なら「今日」、未満なら「今週」です。
4. それ以外は、**カテゴリ**のラベルだけを付けます。

この質問の分け方と判定の順番は、[withoneai/jev-email-classifier](https://github.com/withoneai/jev-email-classifier) を下敷きにしています。

## 6. 安全のためのしくみ

### 付けられる権限と、実際にすること

Gmail には「ラベルを付けるだけ」の権限がありません。ラベルを付けるには `gmail.modify` が要り、この権限があれば読む、送る、ゴミ箱に移すこともできてしまいます（完全な削除はできません）。
そのため「ラベルを付けるだけ」は、権限ではなく**コードで守っています**。

- コードが呼ぶ Gmail の操作は、次の6つだけです。
  - プロフィールの取得
  - メールの一覧
  - メール1通の取得
  - ラベルの一覧
  - ラベルの作成
  - ラベルの追加（`batchModify` の `addLabelIds` だけ）
- `test/safety.test.js` が、ほかの Gmail 操作（ラベルの削除、送信、ゴミ箱など）がコードに入ったら失敗します。
- メールを完全に削除できる `https://mail.google.com/` は使いません。

マニフェスト（`src/appsscript.json`）で求める権限は、次の5つだけです。

| 権限 | 使い道 |
|---|---|
| `gmail.modify` | メールを読み、ラベルを付ける |
| `script.external_request` | AI サービスに接続する |
| `script.scriptapp` | 15分ごとの自動実行を作る |
| `spreadsheets.currentonly` | このスプレッドシートだけを読み書きする（ほかのファイルは見えません） |
| `script.container.ui` | メニューと設定画面を出す |

### 共有の見張り

このスプレッドシートを編集できる人は、スクリプトも書き換えられます。そして自動実行は、**持ち主の Gmail 権限で**動きます。
つまり、編集できる人はあなたのメールを読むコードを仕込めます。そこで、実行のたびに次を確かめ、当てはまったら止まります。

- 共有ドライブに置かれている（持ち主がいない）。
- 持ち主が自分ではない。
- 自分以外に編集者がいる。

この見張りは、うっかり共有したときに止めるためのものです。悪意のある編集者なら見張りのコードごと消せるので、**共有しないこと**がいちばん大切です。
もう1つ限界があります。「リンクを知っている全員が編集可」という共有は、権限の範囲（Drive の権限を求めていません）では見つけられません。リンク共有を「編集者」にしないでください。

### 通信先の固定

- 接続先の URL はコードに固定されています。変えられるのは Cloudflare のアカウントIDだけで、32文字の英数字（0-9, a-f）でなければ受け付けません。設定を書き換えても、別の場所にはメールを送れません。
- マニフェストの `urlFetchWhitelist` でも、上の2つ以外への接続を止めています。「接続テスト」で、この制限が実際に効いているかを確かめます。
- リダイレクトには従いません（APIキーを付けたまま別の場所へ転送されないため）。

### 送る内容と残す内容

- AI に送る内容は、[1章](#会社のルール)に書いた項目だけです。
- シートに残すのは判定結果、差出人、件名だけで、本文は残しません。
- 実行ログ（Apps Script の「実行数」）にメールの内容が残らないよう、コードはログを出しません。エラーメッセージにも件名などを入れません。
- 件名が `=IMPORTXML(...)` のように数式に見えるメールでも、シートでは数式として動かないように、先頭に `'` を付けて書き込みます。

### APIキー

- キーは UserProperties（あなたのアカウントと、このスクリプトに結び付いた保存場所）に入ります。シートには書きません。画面に表示することもありません。
- 空白や改行を含むキーは受け付けません。HTTP ヘッダーに余計な行を入れられないようにするためです。
- Cloudflare では、Workers AI の権限だけを付けたトークンを使ってください。漏れたときの被害が、その権限の範囲で済みます。

## 7. 配布する人の手順

### テンプレートを作る

1. 新しいスプレッドシートを作ります。
2. 「拡張機能 → Apps Script」を開きます。
3. 左の「プロジェクトの設定」で「『appsscript.json』マニフェスト ファイルをエディタで表示する」をオンにします。
4. `src/` の中のファイルを、同じ名前で作って貼り付けます。
   - `.gs` はスクリプト
   - `SetupDialog.html` は HTML
   - `appsscript.json` は既存のものを置き換え
   - [clasp](https://github.com/google/clasp) を使う場合は、`.clasp.json.example` を `.clasp.json` にコピーし、`scriptId` を入れて `clasp push` します。
5. エディタで関数 `resetForDistribution` を選んで実行します。
   - シートが作られます。
   - 配布する人自身のキー、自動実行、記録が消えます。
   - 許可を求められたら許可します。これは配布する人自身のアカウントへの許可で、コピーには引き継がれません。
6. 不要な「シート1」があれば消します。

### 配る

1. 共有設定を「リンクを知っている全員（社内）」の**閲覧者**にします。**編集者にはしないでください。**
2. URL の末尾にある `/edit…` を `/copy` に置き換えたリンクを配ります。開いた人には「コピーを作成」の画面が出ます。

コピーには、スクリプトとシートが引き継がれます。キー（UserProperties）、自動実行、ほかの人の許可は**引き継がれません**。
配る前には毎回、`resetForDistribution` で記録を消してください。

### 更新するとき

利用者のコピーは自動では更新されません。新しい版を配り、各自にコピーを作り直してもらいます。
作り直す前に、古いコピーで「自動実行を止める」を選んでもらってください。古いコピーの自動実行が残っていると、同じメールを二重に判定します。カテゴリと設定の行は、新しいコピーに写せばそのまま使えます。

## 8. 開発とテスト

Google のサービスに触れない部分（判定、応答の解析、設定の検証、本文の取り出し、記録の行、実行の流れ）は、Node.js（20以降）でテストできます。

```sh
npm test
```

- `test/harness.js` は、`src/*.gs` を Apps Script と同じように1つの実行環境に読み込みます。Google のサービスは小さな偽物に差し替えます。
- `test/fixtures/` には、Jev と Clef の応答の例が入っています。Clef の例は、Workers AI の `{ result, success, errors, messages }` で包まれた形です。
- `test/safety.test.js` は、コードの安全上の約束を機械的に確かめます。
  - Gmail の操作はラベルの追加だけ。
  - 通信先は決まった場所だけ。
  - 権限はマニフェストのとおり。
  - キーをログに出さない。
  - 公開される関数は決まったものだけ。

ファイルの構成は次のとおりです。

| ファイル | 中身 |
|---|---|
| `src/Classifier.gs` | 4つの質問、応答の厳密な解析、判定の方針 |
| `src/Providers.gs` | Jev と Clef の違い（URL、キー、応答の包み方、エラーの扱い） |
| `src/Gmail.gs` | Gmail とのやりとり、本文の取り出し（文字コード、HTML、引用の除去） |
| `src/Config.gs` | 設定とカテゴリのシートの読み込みと検証、シートの作成 |
| `src/Sheets.gs` | 記録と実行履歴のシート |
| `src/Main.gs` | 1回の実行の流れ（再試行、時間の上限、ラベル付け） |
| `src/Setup.gs` | メニュー、設定画面、接続テスト、自動実行、共有の見張り |
| `src/SetupDialog.html` | 設定画面 |

## 9. わかっている制約

- **1回あたり約4分半**で、新しい判定を始めるのをやめます。Apps Script の実行は6分までなので、そこで途中で切れないようにしています。終わらなかった分は、次の回に回ります。
- **一時的なエラー**のとき（429、529、5xx）は、短く待って最大3回まで再試行します。それでもだめなら、その回は止めて次の回に任せます。
- **キーが正しくない、設定がおかしい**など、直さないと動かないエラーのときは、自動実行を失敗として終えます。Google から失敗の通知メールが届きます。
- **実機で確かめていない点**があります。どれも「接続テスト」で確かめるか、どちらの場合でも動くように作っています。
  - Gmail がメール本文を、送られてきたときの文字コードのまま返すのか、UTF-8 に直して返すのかは、文書に書かれていません。コードは両方の読み方を試し、文字化けの少ない方を使います。
  - Clef が日本語のカテゴリ名をそのまま選択肢として受け付けるか。接続テストでは、あなたの実際のカテゴリで1回判定します。
  - マニフェストの通信先の制限が、自分のスクリプトでも効くか。接続テストで、許可していない URL に接続できないことを確かめます。
- 「Gmailで開く」のリンクは、ブラウザで最初にログインしているアカウント（`/u/0/`）で開きます。
- 受信トレイにあるメールだけを判定します。アーカイブ済みのメールや迷惑メールは判定しません。
